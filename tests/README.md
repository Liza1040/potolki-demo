# Проверки

Скрипты на `puppeteer-core`, управляют установленным Chrome. Отдельного
тест-раннера нет — это осознанно: для лендинга хватает сценарных проверок.

## Как запускать

Нужен один раз в этой папке:

```bash
npm init -y
npm i puppeteer-core
```

Путь к Chrome задан в скриптах константой `CHROME` — поправьте, если у вас
он лежит иначе.

Проверки идут против **продакшен-сборки**:

```bash
# в корне проекта
npm run build && npm start

# в другом терминале, отсюда
node preflight.mjs
node full-page-test.mjs
```

**После каждого `npm run build` перезапускайте `npm start`.** Иначе старый
процесс отдаёт HTML прежней сборки с несуществующими именами чанков —
получите ошибки 500 и недостоверные замеры.

## Что где

| Скрипт | Проверяет |
|---|---|
| `preflight.mjs` | консоль без ошибок, отсутствие `console.log`, один `h1` и иерархия заголовков, битые ссылки и якоря, кликабельность телефона, 404, работа без JS, метатеги и их длины, JSON-LD, ширины 360/768/1440 |
| `full-page-test.mjs` | сценарии квиза и формы: автопереход, сохранение ответов при возврате, валидация, маска телефона, расчёт вилки, отправка, `source`, FAQ с клавиатуры |
| `metrika-test.mjs` | долёт целей в Метрику. Требует `NEXT_PUBLIC_METRIKA_ID` в `.env.local` и dev-сервер на порту 3001 |
| `make-icons.mjs` | генерация иконок и `favicon.ico`. Запускать только при смене логотипа |

## Грабли, заложенные в скрипты

- **Клик по координатам может перехватить липкая шапка** — для проверок
  используется DOM-клик через `page.$eval`.
- **Нужно дожидаться гидратации**: до неё клик по кнопке отправки уходит
  нативным сабмитом и перезагружает страницу.
- **`--window-size` в headless Chrome не эмулирует мобильный вьюпорт**,
  а обрезает кадр. Используется `page.setViewport`.
